基准：本机已安装的 Intel NUC Software Studio `1.44.25758.0`，其 MSIX SHA-256 为 `3e14be6b8e38009e2d2d15b95e41adaac86b349fb2da8ec4867cff0d458383ff`。2026-10-19 在 LAPKC71E 上观察原版首页、性能、显示、键盘、光条、监视器页面；用 REA 检查原版托管程序集方法，并读取本机 `GetSupportedFeatures()`。静态存在不等于本机可用，界面显示不等于写入成功。

状态：`已接入`=有真实命令及至少部分读回；`部分`=只实现原版的子集或只能报告请求；`缺失`=没有可用控制；`设备未展示`=MSIX 内有模块但本机原版 UI 未开放。所有写入均须在本机做「初值→请求→读回/明确无读回」验收，不能把静态分析当成通过。

## MSIX 中存在、但这台设备原版首页未显示的模块

`PeripheralSettingsMgr`（外设/定时设置）、`SystemPerformanceMgr` 的其它机型分支、`UserPresenceMgr`、`AlexaLightBarMgr`、`CustomizationMgr`、`FeatureMgr`。本机 `GetSupportedFeatures()` 仅报告 `KeyboardLedIndividualKeyControl`、`LightbarSingleColor`、`CpuPowerMode`、`FanPowerMode`、`SystemMonitor`、`DisplaySettings`、`KeyWinLock`、`KeyFnLock`、`KeyNumPad`、`KeyOSD`、`BatteryChargeLimit`、`WhisperMode`。不得将包内程序集存在误称为该设备可用功能；若将来设备能力变化，再扩展矩阵。

## 打包门槛

### 功能完成后的工业化界面验收（尚未开始）

按用户确认的顺序，先完成本表所有本机原版可用功能及必要实机验收，再使用 `ui-ux-pro-max` 统一设计；不得用视觉完成度掩盖仍为“部分”或无法读回的控制项。设计方向以 Intel NUC Software Studio（MSIX）的桌面控制台为参照，保留现有深蓝/青蓝识别，不采用技能检索中面向营销网页的横向叙事、悬浮 CTA、卡片缩放和在线字体依赖。

- 采用统一的 8 px 间距节奏、标题/正文/辅助信息字号层级、对齐基线和控件高度；相同类型的状态、数值、单位与操作按钮在所有页面位置一致。
- 首页、性能、EC 风扇、显示、键盘、光条、监视器使用稳定的栅格与一致的导航/返回方式；窄窗口允许纵向滚动，不裁切内容，也不出现横向滚动。至少检查 850×600、1220×686、1600×900，并在实际 Tauri 窗口检查缩放与最大化/还原。
- 每项设置同时说明控制器和状态来源：EC、NUCtool.dll、官方服务；区分“硬件已读回”“请求已发送，无法确认”“暂不可用”“部分成功”。错误要给原因和安全的下一步，不能只靠颜色表达。
- 图标统一为一套 SVG/矢量图标，不用文字/emoji 混充；保持清晰的点击、悬停、禁用及键盘焦点状态。操作超过 300 ms 应有进度反馈；尊重减少动态效果的系统设置。
- 在真实桌面窗口核对正常、无硬件响应、读回失败和服务不可用状态；普通文字对比度以 4.5:1 为最低目标，所有输入有可访问标签，提示可被辅助技术读取。
- 界面收尾必须逐项回归功能对照表，不得让“整齐排版”改变控制命令、读回判断或 EC/厂商服务互斥规则。
